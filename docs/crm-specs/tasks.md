# ElMiCo CRM - Σχέδιο υλοποίησης

Τα παρακάτω είναι πακέτα υλοποίησης και η πραγματική κατάστασή τους καταγράφεται στο [implementation-status.md](implementation-status.md).
Η έγκριση επιχειρησιακών αποφάσεων δεν αλλάζει την κατάσταση των tests ή των εργασιών σε ολοκληρωμένη.
Οι τεχνικές απαιτήσεις και τα κριτήρια αποδοχής εφαρμόζονται ανεξάρτητα από ώρες και κόστος.
Κάθε πακέτο υλοποιείται σε μικρά βήματα με τη διαδικασία [spec driven development και TDD](development-workflow.md).
Η ανάπτυξη νέων features δεν ξεκινά πριν ολοκληρωθεί επιτυχώς ο έλεγχος βάσης G01 που ακολουθεί.
Οι ακριβείς οδηγίες έναρξης και η προεπιλεγμένη σειριακή εκτέλεση βρίσκονται στο [START_HERE.md](START_HERE.md).

Τα migrations των νέων καταλόγων και επαναλήψεων ανήκουν στα W05 και W06 και δεν υλοποιούνται πριν από το G01.

**W03 handoff - ιδιωτικό αρχείο ρυθμίσεων CRM**

Κατάσταση υποεργασίας config loader: **IMPLEMENTED_LOCAL / AT-56 PARTIAL**.
Ο κοινός loader και οι web/CLI consumers έχουν υλοποιηθεί και ελεγχθεί τοπικά με ιδιωτικά fictional αρχεία και πραγματική απομονωμένη MariaDB.
Το pre-prod Plesk, η επιβεβαίωση runtime λογαριασμών/permissions και το encrypted backup/restore παραμένουν ανοιχτά.
Οι παρακάτω οδηγίες διατηρούνται ως checklist επανελέγχου και εγκατάστασης· τα πραγματικά αποτελέσματα καταγράφονται στο `implementation-status.md`.

- Διάβασε πρώτα τα `START_HERE.md`, `requirements.md` (CFG-01/02), `design.md` και `acceptance.md` (AT-56), καθώς και το σχετικό deployment τμήμα στο `deployment.md`.
- Πρόσθεσε ένα κοινό config loader/bootstrap που φορτώνει αρχείο PHP εκτός repository και document root. Το αρχείο επιστρέφει array ρυθμίσεων, δεν παράγει output και δεν περιέχει/φορτώνει ρυθμίσεις από WordPress `wp-config.php`.
- Σύνδεσε web και CLI bootstraps στον ίδιο loader. Έλεγξε τα υπάρχοντα σημεία `ACCOUNTANT_CRM/includes/db.php`, `includes/security_events.php`, `includes/session.php` και CLI scripts με `getenv()`· διατήρησε τη λειτουργία του τοπικού Docker/test περιβάλλοντος και το test-only `APP_ENV` guard.
- Καθόρισε και τεκμηρίωσε πώς επιλέγεται η εξωτερική διαδρομή config για κάθε περιβάλλον χωρίς να απαιτούνται παραγωγικά secrets στο repository. Μην αποφασίσεις πραγματική Plesk διαδρομή ή permissions πριν επιβεβαιώσεις document root, PHP/CLI execution users και δυνατότητες του File Manager.
- TDD: πρώτα πρόσθεσε tests για έγκυρο config, ελλιπείς/άκυρες τιμές και ασφαλή αποτυχία χωρίς secret/path στο output. Μετά κάλυψε ότι web και CLI φορτώνουν την ίδια πηγή. Χρησιμοποίησε μόνο πλασματικά test values και isolated test setup.
- Έλεγξε ότι το `CRM_SECURITY_HMAC_KEY` έχει τουλάχιστον 32 χαρακτήρες, αριθμητικές ρυθμίσεις είναι έγκυρες, credentials δεν καταγράφονται και η αποτυχία φόρτωσης δεν αποκαλύπτει filesystem paths.
- Για pre-prod, εκτέλεσε το AT-56: αρχείο έξω από public root/repository, ελάχιστα permissions χωρίς ανάγνωση από όλους, HTTP denial, web/CLI read access, ίδια pre-prod DB/HMAC config και encrypted backup/restore με ελεγχόμενη πρόσβαση. Αφαίρεσε αμέσως κάθε προσωρινό diagnostic.
- Ενημέρωσε `implementation-status.md` με τα πραγματικά RED/GREEN αποτελέσματα και ακριβείς εντολές. Μην σημειώσεις AT-56 ή W03 ως ολοκληρωμένο πριν από τα αντίστοιχα αποδεικτικά.

**G01 - Υποχρεωτικός έλεγχος πριν από τα νέα features**

- [ ] Υπάρχει καταγραφή των γνωστών bugs, των ευρημάτων W01 και των entrypoints της υπάρχουσας εφαρμογής.
- [ ] Έχουν διορθωθεί τα γνωστά κενά authentication και authorization, οι συνεδρίες, το logout, τα passwords και ο περιορισμός προσπαθειών.
- [ ] Έχουν διορθωθεί CSRF, GET διαγραφές, XSS, μη ασφαλή queries και χειρισμός ιδιωτικών αρχείων στα υπάρχοντα σημεία.
- [ ] Έχουν διορθωθεί τα γνωστά λειτουργικά bugs, συμπεριλαμβανομένων διπλού session, nested import include, Dompdf, διαδρομών διαγραφής και parsing ποσών.
- [ ] Κάθε επιβεβαιωμένο bug έχει regression test με παρατηρημένο RED πριν από τη διόρθωση και GREEN μετά από αυτήν.
- [ ] Η υπάρχουσα λειτουργία πελατών, εργασιών, συνεργατών, ημερολογίου, imports και exports περνά τους σχετικούς ελέγχους χωρίς τα νέα features.
- [ ] Τα σχετικά baseline tests, syntax/lint και έλεγχοι dependencies περνούν χωρίς ανεπίλυτη αστάθεια.
- [ ] Δεν υπάρχει ανοιχτό επιβεβαιωμένο λειτουργικό bug ή κρίσιμο/υψηλό εύρημα ασφάλειας της υφιστάμενης εφαρμογής.
- [ ] Υπάρχει ανεξάρτητη QA της διορθωμένης βάσης και ανθρώπινη επιθεώρηση των βασικών ροών.
- [ ] Το PASS έχει καταγραφεί με πραγματικό commit, εντολές, αποτελέσματα και σαφή έκταση ελέγχου.

Τα σενάρια που περιέχουν νέα πεδία ή οθόνες εκτελούνται πριν από το G01 μόνο ως προς την ήδη υπάρχουσα συμπεριφορά τους.
Το πλήρες AT-02 για τις νέες οθόνες καταλόγων και το AT-26 για εμφάνιση νέου μέσου δεν χαρακτηρίζονται PASS πριν υλοποιηθούν στο W05.
Το baseline PASS δεν είναι τελικό production PASS και δεν παρακάμπτει τους μελλοντικούς ελέγχους των νέων features.
Οι έλεγχοι πραγματικού Plesk scheduler και backup/restore παραμένουν προϋποθέσεις δημοσίευσης και δεν εμποδίζουν από μόνοι τους την τοπική ανάπτυξη μετά το G01.

**Κανόνες εκτέλεσης**

- Κάθε νέο ή διορθωμένο τμήμα συμπεριφοράς ξεκινά από απαίτηση και AT, με παρατηρημένο RED, GREEN υλοποίηση και REFACTOR με περασμένα tests.
- Κάθε πακέτο χωρίζεται σε μικρές συμπεριφορές αντί να υλοποιείται ολόκληρο πριν γραφτούν tests.
- Για κάθε αλλαγή καταγράφονται απαίτηση, AT, πραγματικά tests και σύντομα αποτελέσματα πριν και μετά την υλοποίηση.
- Στο τέλος ουσιώδους βήματος ενημερώνεται το `implementation-status.md` για ασφαλή συνέχεια σε νέο session.
- Πριν από το τέλος κάθε turn ενημερώνονται η κατάσταση πακέτων, τα αποτελέσματα AT και το επόμενο βήμα και δίνεται στον χρήστη η σύντομη αναφορά προόδου του `START_HERE.md`.
- Η χρήση του SET και η απομόνωση του test περιβάλλοντος ακολουθούν τους ρητούς κανόνες του `development-workflow.md`.
- Οι διορθώσεις ξεκινούν με αναπαραγωγή της προβληματικής συμπεριφοράς όσο γίνεται πιο κοντά στη χρήση τελικού χρήστη.
- Δεν εισάγονται νέα business δεδομένα ή πραγματικοί πελάτες στα fixtures.
- Η υλοποίηση γίνεται στο CRM repository σε branch `codex/`, με διακριτά reviewable βήματα.
- Οι προδιαγραφές μεταφέρονται στο CRM repository πριν από την πρώτη σχετική αλλαγή και το παρόν αντίγραφο σημειώνεται ως σχεδιαστικό στιγμιότυπο όταν υπάρξει επίσημη νέα θέση.
- Δεν γίνεται σιωπηρή αλλαγή απαιτήσεων για να περάσουν τα tests.
- Αν προκύψει διαφορετική συμπεριφορά, ενημερώνονται η απαίτηση, ο σχεδιασμός και το αντίστοιχο σενάριο πριν ολοκληρωθεί η αλλαγή.
- Προϋπάρχουσες αποτυχίες tests/lint και flaky έλεγχοι αντιμετωπίζονται και καταγράφονται.
- Εμφανή εκτός αντικειμένου προβλήματα εμφάνισης αναφέρονται για απόφαση αντί να αλλάζει αυθαίρετα ο σχεδιασμός.
- Η ανεξάρτητη QA επιθεωρεί και αναφέρει, χωρίς να τροποποιεί από μόνη της παραγωγικό κώδικα.
- Δεν τροποποιούνται χειροκίνητα auto-generated αρχεία ή `CHANGELOG.md`.

**Κριτήριο ολοκλήρωσης**

Η ολοκλήρωση πακέτου εξαρτάται από τα πραγματικά αποτελέσματα των απαιτούμενων ελέγχων.
Δεν υπάρχει χρονικό ή οικονομικό όριο που να αντικαθιστά το G01, την ακεραιότητα δεδομένων ή την τελική QA.
